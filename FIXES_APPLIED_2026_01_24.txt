ISSUE 2: KeyError: 'None_sm' - Missing Theta Parameter Handling
==============================================================

Problem:
  Specs with `box_cox_exponent: null` (no consumption theta) caused crash:

  KeyError: 'None_sm'

  at estimation_engine.py line 193:
    theta_c = params[theta_c_name]  # Where theta_c_name = 'None_sm'

Root Cause:
  When YAML has `box_cox_exponent: null`, the spec parser sets:
    utility_consumption_theta = None

  But estimation_engine.py tried to unconditionally access:
    theta_c_name = f"{spec.utility_consumption_theta}{gender_suffix}"
    theta_c = params[theta_c_name]

  This creates 'None_sm' which doesn't exist in params dict.

Solution Implemented:
  ✅ Added conditional checks in 4 key functions:

  1. _compute_utility_singles() - Line 186-205
     Before: theta_c = params[theta_c_name]  # CRASH if None!
     After:  if spec.utility_consumption_theta:
               theta_c = params[theta_c_name]
             else:
               theta_c = 0.0  # Log utility

  2. _compute_utility_derivatives_singles() - Line 599-618
     Same fix for gradient computation

  3. _compute_utility_couples() - Line 983-1004
     Handle both leisure and consumption thetas being None

  4. _compute_utility_derivatives_couples() - Line 1381-1406
     Handle both leisure and consumption thetas being None in gradients

  5. Theta derivative sections - Lines 659-667, 1518-1559
     Only compute derivatives if theta parameters exist:

     Before: idx_theta_c = spec.get_param_index(theta_c_name)
     After:  if spec.utility_consumption_theta:
               idx_theta_c = spec.get_param_index(theta_c_name)
               ...

Files Modified:
  - scripts/enhanced/estimation_engine.py (4 functions, 7 locations)

Changes Summary:
  • Box-Cox theta = None now safely interpreted as log utility (theta = 0.0)
  • Gradient computation skips None theta parameters
  • All 4 specification types now work correctly
