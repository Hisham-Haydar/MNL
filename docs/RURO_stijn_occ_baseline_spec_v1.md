**Save as:** `RURO_frozen_baseline_M0_stijn_occ_v1.md`

## 1. Baseline name

`M0_stijn_occ` — Stijn-style enhanced RURO with one additive occupation-opportunity layer using EUROMOD `loc` collapsed to `loc4` (four tasks).

YAML file: `scripts/enhanced/estimation_spec_stijn_occ_M0.yaml`.
Output tag: `M0_stijn_occ`.

This is the **first reportable specification** of the Stijn-style enhanced branch and the entry point for the welfare layer of the JMP. It is downstream of and depends on the pipeline fixes in §14.

---

## 2. Choice unit

The choice unit is the **household**, with four jointly estimated groups:

- `sm` — singles male
- `sf` — singles female
- `cm` — couples, male partner block
- `cf` — couples, female partner block

France 2016 RURO-eligible sample: ~1,676 singles households and ~2,577 couples households → 4,253 households estimated jointly.

`dwt` is read into the MNL files for descriptives only. The MNL likelihood is **unweighted** at `M0`.

For couples: `β_c`, `θ_c` are shared on household consumption `C`; leisure utility and all opportunity blocks are partner-specific and partner-additive.

EUROMOD system: `fr_2016`.

Inclusion: `ruro_sample == 1`, the flag built in `enh_RURO_prep.py`. RURO-eligible deciders only.

The job-choice / GMM branch (`scripts/Job_model/`) is **not** used at `M0`. Cross-branch comparison is `M7`, out of scope here.

## 4. Alternative definition

100 alternatives per household, generated by `enh_RURO_draws.py` (continuous-draws branch).

Per individual, an alternative is:

- **Non-employment**: `(e=0, h=0, w=0, loc4=-1)`. By convention `q_H = q_W = q_Occ = 1`, i.e. `log_q_H = log_q_W = log_q_Occ = 0`.
- **Working** (`e=1`): `(h, w, loc4)` where
  - `h` is a continuous draw in `[h_min, h_max]` (uniform proposal acceptable; empirical proposal allowed if documented in `mnlmeta.json`).
  - `w` is a continuous draw in `[w_min, w_max]`.
  - `loc4 ∈ {1, 2, 3, 4}` is a categorical draw from the empirical occupation share among working RURO-eligible deciders.

For couples, an alternative is a joint pair of singles-style alternatives, one per partner, with **conditionally independent partner draws** at `M0`.

Per-alternative `loc4` variation across the 100 alternatives of a household is **required**. Without it, `β_occ_k` is not identified. See §14 and §15.

---

## 5. Proposal distribution

Per individual, factorized:

```
q(e, h, w, loc4 | X) = q_E(e | X) · 1{e=1} · q_H(h | X) · q_W(w | X) · q_Occ(loc4 | X)
```

On the log scale, stored per row in the MNL file:

```
log_q = log_q_E + working · (log_q_H + log_q_W + log_q_Occ)
```

Where `working = 1{h > 0}`.

For couples: `log_q_couple = log_q_male + log_q_female`, with each partner block factorized as above.

**`q_Occ` definition at `M0`:** a **single unconditional empirical occupation share** over `loc4` among working RURO-eligible deciders (`ruro_sample == 1 & is_worker == 1`), computed once over the pooled sample and reused for every household and every draw. No conditioning on region, education, gender, or age. Source recorded in `mnlmeta.json` as `q_Occ_source = "empirical loc4 share, working RURO-eligible deciders, France 2016 (pooled across SM/SF/CM/CF)"`.

Gender-specific `q_Occ` is **not** used at `M0`. It is a clean later extension if `β_occ_k` SEs are unstable.

## 6. Preference utility

Box-Cox in normalized consumption and normalized leisure. No consumption–leisure interaction. No within-couple leisure–leisure interaction. No `loc4` in utility.

**Singles** (`g ∈ {sm, sf}`):

```
U_g(C, L; Z) = β_c_g · BC(C, θ_c_g) + β_l_g(Z) · BC(L, θ_l_g)

β_l_g(Z) = β_l0_g
         + β_l_age_g     · age_norm
         + β_l_age2_g    · age_norm²
         + β_l_nkids_g   · n_children       (only g = sf)
         + β_l_educH_g   · educH
```

**Couples**:

```
U(C, L_m, L_f) = β_c · BC(C, θ_c)
               + β_l_m(Z_m) · BC(L_m, θ_l_m)
               + β_l_f(Z_f) · BC(L_f, θ_l_f)
```

where `β_l_m(Z_m)` and `β_l_f(Z_f)` have the same shape as the singles leisure coefficient, with `n_children` entering only the female partner block.

**Consumption source.** `C` is normalized household disposable income built from EUROMOD `ils_dispy` (12 components per the standard income concepts table). Singles: `consumption = max(ils_dispy, 1.0)`. Couples: `consumption = max(ils_dispy_male, 1.0) + max(ils_dispy_female, 1.0)`. `C = consumption / c_scale` where `c_scale` is the mean across the household's 100 alternatives. **`ils_origy − ils_tax − ils_sicee` reconstructions are forbidden** and must trigger an audit failure. The MNL build must record `consumption_source = "ils_dispy"` (or `"ils_dispy_em"` if the EUROMOD recomputed version is used) in `mnlmeta.json`.

**Leisure source.** `L = max(80.0 − h, 1.0) / l_scale` (singles), with partner-specific equivalents for couples. The constant `80.0` is the existing pipeline convention.

**`educL` not in utility at `M0`.** The pipeline supports it, but to keep utility shifters and wage shifters cleanly separated across blocks (§13), `educL` enters wage opportunity only. `educH` enters leisure utility and `O^E` (separately, by exclusion restriction §13). This is a deliberate restriction relative to v3 and to v4 §8; it is the simpler choice and the one closest to Stijn's R implementation.

**`loc4` does not enter utility.** Hard constraint, enforced by the spec parser.

## 7. Labour-time opportunity

```
O^E_hj + O^H_hj
  = β_E       · 1{h_j > 0}
  + β_pt1     · 1{h_j ∈ PT1}
  + β_pt2     · 1{h_j ∈ PT2}
  + β_ft      · 1{h_j ∈ FT}
  + β_gsur    · gsur · 1{h_j > 0}
  + β_E_educH · educH · 1{h_j > 0}
```

Focal-point bands (locked from the existing pipeline):

- PT1: `h ∈ [18.5, 21.5]`
- PT2: `h ∈ [29.5, 30.5]`
- FT:  `h ∈ [37.5, 40.5]`

All terms are gated by `working = 1{h > 0}`. `working` is built from EUROMOD `lhw` and `les` via `_compute_is_worker` in `enh_RURO_prep.py`.

`β_E` is **estimated**, not normalized to 0. It pins the market-vs-non-market log-odds and is identified off the participation margin net of `−log q_E`.

`gsur` is built by `enh_prepare_FR_gsur.py` and enters `O^E` only (exclusion restriction §13).

Partner-additive for couples, partner-specific covariates.

`loc4` does **not** condition `O^H` at `M0`.

## 8. Wage opportunity

Log-normal density per working alternative:

```
log f_W(w | X) = − 0.5 · z² − log σ − log w
z              = (log w − μ(X)) / σ
μ(X)           = β_w0 + β_w_educL · educL + β_w_educH · educH + β_w_pexp · pexp + β_w_pexp² · pexp²
σ              > 0
```

For `e = 0`: `O^W = 0`.

The `−log w` Jacobian is **mandatory** in both engines (NumPy/SciPy and GAMSPy vectorized). The audit must verify it on both code paths.

Observed wage `w` is built from EUROMOD `yem` (monthly gross employee income) divided by hours per the project convention in `enh_RURO_prep.py`. The wage column carried into the density is `wage_for_draws` / `wage_ruro` / `wage`, as currently named; locked by the audit, not renamed at `M0`.

`σ` is **shared across occupations** at `M0`. The Mincer mean does not depend on `loc4`.

`educL`, `educH`, `pexp`, `pexp²` enter `O^W` only (exclusion restriction §13).

Partner-additive for couples.

`O^W | loc4` is `M3`, not `M0`. Forbidden here.

## 9. Occupation opportunity using ISCO / LOC

A new additive log-density block, named `occupation_opportunity` in the YAML, distinct from any existing `market_opportunity` block in the parser.

**Variable used at `M0`:** `loc4` (four-task collapse of EUROMOD `loc`), with categories
- `1` routine-manual (**reference**, omitted)
- `2` nonroutine-manual
- `3` routine-cognitive
- `4` nonroutine-cognitive

Per individual:

```
O^Occ_hj = β_occ_2 · 1{loc4_j = 2} · 1{h_j > 0}
         + β_occ_3 · 1{loc4_j = 3} · 1{h_j > 0}
         + β_occ_4 · 1{loc4_j = 4} · 1{h_j > 0}
```

**Gender pooling at `M0`:** parameters are **gender-specific**, not pooled. That gives `β_occ_2_sm, β_occ_3_sm, β_occ_4_sm` for singles male, and analogously for `sf`, `cm`, `cf`. Total: 12 occupation parameters across the four gender groups.

Rationale for keeping gender split: occupation distributions differ sharply by gender in France 2016 (`loc4 = 2` nonroutine-manual is male-dominated; `loc4 = 4` nonroutine-cognitive is more balanced but with different age/education profiles by gender). Pooling would bias `β_occ_k` toward the larger gender stratum.

**Why `loc4` and not `loc` (ISCO 1-digit) at `M0`:** the audit confirms that `loc4` is the cleaner column carried in the continuous-branch pipeline (with `−1` non-worker and `−2` unknown-worker sentinels). `loc` adds 5 more parameters per gender (8 instead of 3), and the audit warns that `loc4 = 2` is already a thin cell in France. Granularity bumps to ISCO 1-digit are `M2`.

**Reference category choice — `loc4 = 1`, routine-manual.** Reasons: (i) it is the modal `loc4` category in France 2016 working deciders by raw count, giving stable interpretation; (ii) it matches the natural Aaberge–Colombino reading of "baseline manual work" against which non-routine and cognitive offers are easier to access; (iii) it avoids using `loc4 = 4` (nonroutine-cognitive) as reference, which would couple `β_occ_k` interpretation tightly to education.

**Hard restrictions:**
- `loc4` enters `O^Occ` **only**. Not in `U`, `O^E`, `O^H`, `O^W`. Enforced by the spec parser cross-block exclusion check.
- `O^Occ` is gated by `working`. For `h = 0`, every indicator times `working` is 0, so `O^Occ = 0` and `loc4 = −1` is consistent with the zero contribution.
- Partner-additive for couples: `O^Occ_couple = O^Occ_male + O^Occ_female`.

`loc4` columns used: singles `loc4`; couples `loc4_male`, `loc4_female`. These must vary per alternative (the audit's blocking issue §15.1).

## 10. Treatment of non-work alternatives

For every alternative with `h = 0`:

- `working = 0`.
- `1{h ∈ PT1}, 1{h ∈ PT2}, 1{h ∈ FT}` all 0.
- `gsur · working = 0`.
- `educH · working = 0`.
- `O^W = 0` (wage density does not contribute).
- `loc4 = −1` (RURO non-worker sentinel from `enh_RURO_prep.py`). Every `1{loc4 = k} · working` is 0 for `k ∈ {2, 3, 4}`, so `O^Occ = 0`.
- `q_H = q_W = q_Occ = 1`, so `log_q_H = log_q_W = log_q_Occ = 0`.
- `log_q = log_q_E(e=0)`.

The non-employment alternative contributes only `U_h,0 − log_q_E(e=0)` to the choice index. `β_E` is identified by the contrast between this and the working alternatives' full bundle of opportunity terms minus `log_q_E(e=1) + log_q_H + log_q_W + log_q_Occ`.

Both `estimation_engine.py` and `gamspy_estimation_vectorized.py` must implement the `· working` gate on every employment-conditional term. The audit must verify this for singles and couples.

## 11. Prior correction

Stored per row in the MNL parquet files:

```
prior      = q on the original scale, strictly positive
log_prior  = log(prior) = log_q_E + working · (log_q_H + log_q_W + log_q_Occ)
```

For couples: `log_prior_couple = log_prior_male + log_prior_female`.

The likelihood subtracts `log_prior` **exactly once** per alternative:

```
V_hj = U_hj + O^E_hj + O^H_hj + O^W_hj + O^Occ_hj − log_prior_hj
```

**Hard assertions, run after every MNL build:**

```python
assert (df["prior"] > 0).all()
assert np.max(np.abs(np.log(df["prior"]) - df["log_prior"])) < 1e-8
assert df.groupby("idhh")["chosen"].sum().eq(1).all()
# Per-layer consistency:
recomputed = (df["log_q_E"]
              + df["working"] * (df["log_q_H"] + df["log_q_W"] + df["log_q_Occ"]))
assert np.max(np.abs(df["log_prior"] - recomputed)) < 1e-8
```

For couples, the per-layer check sums male and female contributions.

**Known blocking bug, must be patched before `M0` runs:** `enh_RURO_prep_mnl_basic.py` lines ~1448–1451 (singles continuous fallback) and ~1572–1575 (couples continuous fallback) currently set `df["prior"] = np.log(prior_density)` and `df["log_prior"] = df["prior"]`. Replace with:

```python
df["prior"]     = prior_density
df["log_prior"] = np.log(prior_density)
```

Even though current runs use the `log_q_total` path and avoid this fallback, the bug must be removed before `M0` is locked, because adding `log_q_Occ` may shift which code path fires.

`mnlmeta.json` must record:
- `q_Occ_source` (per §5),
- `proposal_layers = ["q_E", "q_H", "q_W", "q_Occ"]`,
- `loc4_nonworker_code = -1`,

## 15. Required diagnostics

Stored in `estimation_results.json` or sidecars:

**Optimizer & likelihood**: status, iteration count, final gradient norm; `joint_ll`, `ll_null_uniform`, `ll_null_prior_corrected`, McFadden ρ², AIC, BIC.

**Hessian**: condition number, number of negative eigenvalues, smallest absolute eigenvalue.

**Per-parameter**: estimate, SE, t-stat, p-value; flag any non-finite SE; flag parameters within `1e-3` of a bound.

**Cross-engine consistency**: at the converged `θ` (and at one perturbed `θ`), `|joint_ll_GAMSPy_vectorized − joint_ll_NumPy_SciPy| / N_obs < 1e-6`. The vectorized GAMSPy Box-Cox uses a 4th-order Taylor expansion; the audit must report pointwise relative error of `BC(x, θ)` between exact NumPy and Taylor GAMSPy at the estimated `θ` values, flagging any cell with relative error `> 1e-3` (this matters because the v3 estimates show `θ` values as negative as `−2`, outside the natural radius of the Taylor approximation).

**Prior diagnostics** (must run after every MNL build, not just at estimation):
- `(prior > 0).all()`
- `max|log(prior) − log_prior| < 1e-8`
- `max|log_prior − (log_q_E + working · (log_q_H + log_q_W + log_q_Occ))| < 1e-8`
- `chosen` sums to 1 per `idhh`.

**Per-alternative `loc4` variation diagnostic** (this is the canary for the principal pipeline modification):
- For singles: median across `idhh` of `loc4.loc[working == 1].nunique()` must be `≥ 3`. If `< 3`, the MNL still has insufficient occupation variation, and `M0` must not be estimated.
- For couples: same check on `loc4_male` and `loc4_female` separately.

**Observed-vs-predicted fit by group** (`sm`, `sf`, `cm`, `cf`): participation rate, mean hours, hours histogram with PT1/PT2/FT bins, wage KDE, **occupation distribution by `loc4` (the new panel)**.

**Seed/draw stability**: re-estimate `M0` with `≥ 2` alternative draw seeds; report max parameter difference. Target: `< 5%` for preference and key opportunity coefficients including `β_occ_k`.

**Recovery test** (Stijn-style, on France-shaped data):
- Fix `θ⁰` for `M0` at plausible values (not the empirical estimates).
- Draw 100 alternatives per household from `q` including `q_Occ`.
- Compute `V_hj⁰` using `θ⁰`, add i.i.d. Gumbel shocks, take argmax as synthetic chosen.
- Re-estimate `M0` from ≥ 3 starts (perturbed `θ⁰`, neutral, random).
- Run `R ≥ 50` Monte Carlo replications.

Recovery pass criteria:
- Mean bias `< 10%` of true value (or `< 0.05` absolute when true value is near 0) for every preference and opportunity coefficient including `β_occ_2`, `β_occ_3`, `β_occ_4` in each gender group.
- 95% coverage in `[0.92, 0.98]` for `β_c`, `θ_c`, `β_l0`, `θ_l`, leading `β_occ_k`, and `β_E`.
- Convergence rate `≥ 90%`.

Until recovery passes, `M0` estimates are **provisional** and must not enter the welfare layer.

## 16. Pass / fail criteria

Three sequential gates. `M0` is reportable only if all three pass in order.

**Gate A — Pipeline readiness** (must pass before any estimation):

A1. All forbidden columns absent from `fr_2016_RURO_mnl__singles.parquet` and `fr_2016_RURO_mnl__couples.parquet`.
A2. All required columns present, including `loc4` (and `_male`/`_female`) varying per alternative per the §15 canary.
A3. Prior diagnostics pass: `(prior > 0).all()`; `|log(prior) − log_prior| < 1e-8`; per-layer consistency `|log_prior − (log_q_E + working · (log_q_H + log_q_W + log_q_Occ))| < 1e-8`.
A4. Continuous-fallback prior bug patched and verified by a unit test that forces the fallback path.
A5. `consumption_source` in `mnlmeta.json` is `"ils_dispy"` or `"ils_dispy_em"`.

**Gate B — Estimation convergence**:

B1. Optimizer converges with status code "optimal" / "locally optimal".
B2. Hessian has **no** negative eigenvalues; condition number `< 1e7`; smallest absolute eigenvalue `> 1e-8`.
B3. All 90 parameters return finite SEs.
B4. No substantive parameter (preference or opportunity) within `1e-3` of a bound. `σ_g` near `0.1` or `20.0` flagged but not blocking.
B5. Seed-stability max parameter difference `< 5%` for `β_c`, `θ_c`, `β_l0_g`, `θ_l_g`, `β_E_g`, `β_occ_2_g`, `β_occ_3_g`, `β_occ_4_g`.
B6. Cross-engine `joint_ll` agreement within `1e-6` per observation at the converged `θ`.

**Gate C — Recovery**:

C1. Stijn-style recovery test passes the §15 criteria for every gender group on at least `β_c`, `θ_c`, `β_l0_g`, `θ_l_g`, `β_E_g`, and at least two of three `β_occ_k_g` per group.
C2. Convergence rate across `R ≥ 50` replications `≥ 90%`.

**Failure handling, in order:**

- If A1–A5 fails → fix the pipeline. Do not estimate.
- If B2 fails (indefinite Hessian) → do not gender-disaggregate `β_occ_k`; estimate with `β_occ_k` pooled across `{sm, cm}` and `{sf, cf}`. Re-check.
- If B5 fails on `β_occ_k` only → switch `q_Occ` to gender-conditional empirical share. Re-check.
- If C1 fails on `β_occ_k` → demote occupation to `M1` and report `M0` without it as a robustness check on the v3 preference findings, *not* as the JMP baseline.
- If C1 fails on preference parameters → do not enter the welfare layer; debug preferences before adding opportunity.
