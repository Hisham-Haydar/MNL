## What GSUR Means Here

GSUR means group-specific unemployment rate.

In this project it is used as an external measure of local/group labor-market tightness. The economic role is:

```text
higher unemployment rate -> lower chance of receiving some job opportunities
```

So the expected sign in an opportunity equation is usually negative, although the exact interpretation depends on the specification and interactions.

Important: GSUR is not generated by the RURO simulation. It is an external labor-market variable merged onto individuals or alternatives.

## What The Preparation Script Does

The preparation script parses a Eurostat-style Excel workbook containing unemployment rates by:

- year;
- French region;
- sex;
- education;
- age group.

It extracts sheet metadata such as:

- education: `TOTAL`, `ED0-2`, `ED3_4`, `ED5-8`;
- sex: `T`, `M`, `F`;
- age group: examples include `Y15-24`, `Y20-64`, `Y25-34`, `Y35-44`, `Y45-54`, `Y55-64`;
- region code: national France and NUTS1 codes such as `FR`, `FR1`, `FRB`, etc.

For the RURO-ready file it then:

1. Keeps male and female rows, excluding total-sex rows for the final lookup.
2. Selects a preferred age group, default `Y20-64`.
3. Uses a fallback chain if the preferred age group is not available:

```text
preferred age group -> Y25-34 -> Y_GE25 -> first available age group
```

4. Maps region codes into the RURO `drgn1` numeric region code.
5. Maps sex into RURO `dgn`:

```text
M -> 1
F -> 0
```

6. Maps education into both text and numeric forms:

```text
ED0-2 -> educL -> educ3 = 0
ED3_4 -> educM -> educ3 = 1
ED5-8 -> educH -> educ3 = 2
TOTAL -> educALL -> educ3 = -1
```

7. Converts unemployment rates from percent into proportions:

```text
gsur = gsur_percent / 100
```

8. Checks uniqueness for:

```text
year, drgn1, dgn, educ3
```

9. If duplicate keys exist, takes the mean GSUR and keeps metadata from the first row.
10. Validates that the final `gsur` values are inside `[0, 1]`.

## Main RURO Lookup Columns

The main output file contains columns such as:

| Column | Meaning |
| --- | --- |
| `year` | calendar/data year |
| `drgn1` | numeric French region code used by the RURO data |
| `region_code` | source NUTS-style region code |
| `region_name` | source region label |
| `dgn` | RURO sex code, male `1`, female `0` |
| `sex` | source sex code |
| `education` | source education group |
| `educ_code` | `educL`, `educM`, `educH`, or `educALL` |
| `educ3` | numeric education group |
| `gsur` | unemployment rate as a proportion |
| `age_group_used` | age group selected during preparation |
| `region_key` | alias for `drgn1` |

## How GSUR Is Merged Into MNL Files

The MNL preparation script accepts:

```text
--gsur-file PATH
```

The relevant implementation functions are:

- `_merge_gsur_singles(...)`;
- `_merge_gsur_couples_wide(...)`;
- `_map_age_to_gsur_group(...)`;
- `_pick_gsur_full_age_fallback(...)`.

### Singles Merge

For singles, the base merge keys are:

```text
year, drgn1, dgn, educ3
```

If the GSUR file has age-group information and the singles data have an age column, the first attempt uses:

```text
year, drgn1, dgn, educ3, age_group
```

The age group is derived from age:

| Age | GSUR age group |
| --- | --- |
| age < 25 | `Y15-24` |
| 25 <= age < 35 | `Y25-34` |
| 35 <= age < 45 | `Y35-44` |
| 45 <= age < 55 | `Y45-54` |
| 55 <= age < 65 | `Y55-64` |
| otherwise/default | `Y20-64` |

If the age-specific merge fails, the code tries a full-age fallback in this order:

```text
Y20-64 -> Y15-74 -> Y_GE15 -> Y_GE25
```

The final singles column is:

```text
gsur
```

### Couples Merge

For couples, GSUR is merged separately by gender.

Male:

```text
year, drgn1, educ3_male
dgn = 1
output column = gsur_male
```

Female:

```text
year, drgn1, educ3_female
dgn = 0
output column = gsur_female
```

If age columns are present, the same age-group logic is applied separately for male and female.

The script can derive `educ3_male` and `educ3_female` from:

- `deh_male` / `deh_female`; or
- `educL_*`, `educM_*`, `educH_*` dummies.

## How GSUR Enters Estimation

### Continuous RURO

In continuous RURO specs, GSUR usually enters an hours/opportunity block.

Examples in older/current specs use parameter names such as:

```text
beta_gsur
beta_gsur_male
beta_gsur_female
```

The economic interpretation is:

```text
effect of group unemployment on the availability/intensity of work alternatives
```

It should not be interpreted as direct utility from unemployment.

### Job-Choice RURO

In job-choice specs, GSUR enters `market_opportunity`.

Example from job-choice specifications:

```yaml
market_opportunity:
  gsur_variable: "gsur"
  offer_only_vars: ["gsur", "reg2", "reg3", "reg4", "reg5", "reg6", "reg7", "reg8"]
```

Typical parameter names:

```text
beta_offer_gsur
beta_offer_gsur_isco1_1
beta_offer_gsur_isco1_2
...
beta_offer_gsur_educM
beta_offer_gsur_educH
beta_offer_gsur_hours_bin_1
...
```

The exact parameter names depend on the chosen job-choice spec.

## Identification Restriction

The parser enforces an important restriction:

```text
gsur cannot appear in utility.leisure.shifters
```

The intended use is:

```text
GSUR belongs in opportunity, not preferences.
```

This matters because the project goal is to separate preference parameters from labor-market opportunity parameters.

If GSUR is allowed to affect utility directly, it becomes harder to argue that GSUR identifies opportunity rather than preferences.

## Current Empirical Caveat

The implementation history says the current French GSUR file effectively uses `Y20-64` fallback coverage.

That means:

- GSUR is present and merged;
- age-group matching exists in code;
- but the active prepared file may not contain rich age-specific variation;
- for current FR runs, much of the merge may use broad working-age unemployment rates.

This is acceptable for an opportunity shifter, but it should be documented in papers/results.

## What To Check Before Estimation

After MNL preparation, inspect:

Singles:

```text
fr_2016_RURO_mnl...__singles.parquet
column: gsur
```

Couples:

```text
fr_2016_RURO_mnl...__couples.parquet
columns: gsur_male, gsur_female
```

Diagnostics to run/check:

- missing rate of `gsur`;
- missing rate by year;
- variation by `drgn1`;
- variation by `dgn`;
- variation by `educ3`;
- whether all values are between 0 and 1;
- whether GSUR is constant within the estimation sample;
- whether job-choice specs keep GSUR only in `market_opportunity`.

## Common Confusions

### GSUR is not generated by GMM

GMM builds the job universe. GSUR is an external labor-market shifter merged later.

### GSUR is not a preference parameter

In the intended specification, GSUR shifts offer/opportunity intensity. It should not enter utility from leisure or consumption.

### GSUR is not the same as sector

GSUR varies by region, gender, education, year, and possibly age group. It does not define the job sector. Sector/occupation opportunity effects require variables such as `isco1` or a future NACE/industry variable.

### `gsur` values should be proportions

The preparation script converts percent into proportions. A value like `0.08` means 8 percent unemployment.
