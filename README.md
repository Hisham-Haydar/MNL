# RURO Labor Supply Model - France

Python research code for estimating French labor-supply models with a Random Utility Random Opportunity (RURO) structure. The repository contains two active empirical branches:

- a continuous RURO branch that draws hours and wages directly;
- a job-choice RURO branch that draws discrete job bundles made from hours, wages, and occupation/sector-like job information.

The repository is being cleaned toward a package layout, but it is still a research codebase first. The reusable package skeleton lives in `src/mnl/`; the production RURO estimation workflow currently lives in `scripts/enhanced/` and `scripts/Job_model/`.

Acknowledgements are centralized in [docs/ACKNOWLEDGEMENTS.md](docs/ACKNOWLEDGEMENTS.md). Personal names are not used as package or model-family names.

## What This Project Does

The project estimates how households choose labor supply alternatives when the available opportunity set is itself random. A household does not choose from every theoretically possible hours/wage/job combination. Instead, the code generates or constructs a finite set of alternatives, runs tax-benefit simulation for those alternatives, and estimates a discrete-choice likelihood that combines:

```text
choice index =
    preference utility
  + labor-time / hours opportunity
  + wage opportunity
  + optional job-market opportunity
  - proposal-density correction
```

The key empirical target is to separate:

- preferences: utility from disposable income/consumption and leisure;
- opportunities: the probability or intensity with which labor-market alternatives are available;
- taxes and transfers: disposable income generated by EUROMOD for each counterfactual alternative.

This separation is the central research object. The code can estimate separate preference and opportunity parameter blocks. The current empirical identification status is more cautious: the job-choice branch is the strongest current candidate; the continuous French branch still needs stronger diagnostics before making final structural identification claims.

## Current Status

The active code can:

- prepare French 2016 EUROMOD microdata for RURO estimation;
- generate continuous RURO draws of hours and wages;
- construct discrete job-choice alternatives from hours bins, wage bins, occupation codes, and latent job types;
- run EUROMOD on counterfactual alternatives;
- build MNL-ready long-format estimation datasets;
- estimate joint singles/couples likelihoods with GAMSPy;
- estimate preference, hours-opportunity, wage-opportunity, and market-opportunity blocks from YAML specifications;
- apply proposal-density corrections;
- produce post-estimation HTML reports and diagnostics.

The project should currently be treated as:

```text
research pipeline: active and usable
package API: early scaffold, not yet the main production interface
```

## Economic Model

### Preferences

Preferences are estimated through a Box-Cox utility function in normalized consumption and leisure.

For singles, the preference component is conceptually:

```text
U =
    beta_c * BC(consumption, theta_c)
  + beta_l(Z) * BC(leisure, theta_l)
  + optional beta_cl interaction
```

For couples, the model uses household consumption plus male and female leisure terms:

```text
U =
    beta_c * BC(household consumption, theta_c)
  + beta_l_male(Z_male) * BC(leisure_male, theta_l_male)
  + beta_l_female(Z_female) * BC(leisure_female, theta_l_female)
  + optional interactions
```

Common preference shifters include:

- age and age squared;
- children;
- education;
- sex-specific or partner-specific variables where the specification includes them.

The detailed parameter-by-parameter explanation is in [docs/methods/RURO_PREFERENCE_ESTIMATION_CAPABILITIES.md](docs/methods/RURO_PREFERENCE_ESTIMATION_CAPABILITIES.md).

### Opportunities

The opportunity side is represented by log-density or log-index terms that enter the same choice index as utility.

Continuous RURO uses:

- non-employment / hours availability;
- focal hours peaks;
- wage opportunity terms;
- optional market opportunity shifters.

Job-choice RURO uses:

- a sampled job universe;
- job proposal densities, carried through `prior`, `log_prior`, and `log_q_*` columns;
- optional market-opportunity parameters in the YAML spec;
- job identifiers such as `job_id`, `hours_bin`, `wage_bin`, and `isco1`.

### Proposal Correction

The code estimates choices from generated alternatives. Because those alternatives are sampled from a proposal distribution, the likelihood corrects for the proposal density:

```text
V = utility + opportunity terms - log(prior)
```

The preferred convention is:

```text
prior     = proposal density or probability on the original positive scale
log_prior = log(prior)
```

The job-choice branch follows this convention in current baseline files. Some continuous fallback code paths should still be tightened before treating the pipeline as fully robust; see [docs/methods/RURO_CURRENT_STATE_AND_IDENTIFICATION.md](docs/methods/RURO_CURRENT_STATE_AND_IDENTIFICATION.md).

## Estimation and Specifications

The active estimator entrypoint is:

```powershell
python scripts\enhanced\enh_RURO_estimate_FR.py
```

Common options include:

- `--mnl-base`: base path for `__singles.parquet` and `__couples.parquet`;
- `--output-dir`: where estimation outputs are written;
- `--group`: estimation group, commonly `joint`;
- `--solver`: for example `gamspy-conopt`;
- `--vectorized`: use the vectorized GAMSPy code path;
- `--spec-config`: YAML specification file;
- `--warm-start`: previous run or `none`;
- `--auto-timestamp`: create a timestamped run folder.

Important estimation infrastructure:

- `scripts/enhanced/estimation_spec_parser.py`: parses YAML specs.
- `scripts/enhanced/estimation_utils.py`: loads and prepares arrays.
- `scripts/enhanced/gamspy_estimation_vectorized.py`: current production vectorized GAMSPy estimator.
- `scripts/enhanced/gamspy_estimation.py`: non-vectorized GAMSPy implementation.
- `scripts/enhanced/estimation_engine.py`: NumPy/SciPy reference implementation.
- `scripts/enhanced/compute_standard_errors.py`: standard-error support.

Outputs normally include:

- `estimation_results.json`
- `estimation_summary.txt`
- group-level CSV parameter files
- `identification_diagnostics.txt` when available
- `specification_used.yaml`

```powershell

```

```powershell

```

Current automated test coverage is minimal. Before making strong claims from new specifications, add or run checks for:

- `prior > 0`;
- `log_prior == log(prior)` within tolerance;
- exactly one chosen alternative per household;
- no missing values in utility/opportunity variables;
- stability across seeds, draw counts, starts, and specifications;
- Hessian condition number and negative eigenvalues;
- recovery on RURO simulated data.

## Glossary

- RURO: Random Utility Random Opportunity.
- MNL: multinomial logit.
- EUROMOD: tax-benefit microsimulation system used to compute disposable income under alternatives.
- GSUR: external unemployment/opportunity-rate input used as an opportunity shifter.
- Proposal density: the probability or density used to generate alternatives before likelihood correction.
- Prior correction: subtracting `log(prior)` from the choice index to correct for sampled alternatives.
- Continuous RURO: branch that draws hours and wages directly.
- Job-choice RURO: branch that constructs and samples discrete job bundles.
- Preference block: parameters governing utility from consumption and leisure.
- Opportunity block: parameters governing the availability/intensity of alternatives.
